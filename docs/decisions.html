Four Networks, One Circuit

A hand-written neural network raced three written by AI agents. Same genetic algorithm, same circuits, same seed — the architecture the only thing that differed. It came down to two frames. This is what was decided, what was measured, and what turned out to be wrong.

01The rules, and why they are these rules

Each entrant is one file in src/brains/ holding a class that turns seven sensor readings plus its own speed into steering and throttle. Dropping the file in is the whole installation: every module in that directory is imported at startup, so the next train.py trains it and the next race.py puts it on the grid.

Two rules do the real work. Everything between the sensors and the controls must be learned. A braking criterion like speed / (speed + distance ahead) is sound engineering and does not belong here — the race compares what evolution finds against what evolution finds, not against what an author already knew. And every entrant must implement describe(), returning its layers and weight matrices, because a network nobody can see is half a submission.

The shape is otherwise free: any number of layers, any number of neurons, any topology, any subset of the sensors. Weights are never trained by gradient descent — there is no gradient to take. Fitness is distance travelled before crashing, and reaching it means passing through a boolean road mask and a discrete death condition, neither of which has a useful derivative.

02What makes the comparison fair

Each entrant keeps its own population — crossing one entrant's genome with another's is meaningless, since the sizes differ and at equal size the genes would mean different things. But there is one draw per evaluation: one circuit, one island layout, one start point, shared by everyone. Parity is a property of the loop rather than a convention someone has to remember.

Training each entrant in its own run did not give this, even on one seed. Start points came from the same generator as the genomes and the breeding, so how many numbers had already been drawn — which depends on genome size — decided where the cars started. Entrants of different sizes met different starts from generation 1. Start points now come from a stream of their own.

04The incumbent shrank, then gained a layer

8 → 14 → 14 → 2  ·  366 params → 8 → 10 → 4 → 2  ·  160 params

100 genomes over 120 generations is 12 000 evaluations, and a derivative-free search wants 100 to 1000 of them per parameter. At 366 parameters that asks for 37 000 at the most generous end. The old default was not short of capacity; it was short of the search to fill it. It was never going to be searched, only sampled.

Cutting to 150 on a single hidden layer of twelve fixed the arithmetic. Depth came back afterwards, and cost almost nothing: two layers at these widths are ten parameters more than one. So the choice was about shape rather than budget.

Reading the ray fan is comparing each ray against its neighbours to find the gap, and then weighing that against own speed to set steering and braking. One matrix has to do both at once; two do them in turn. Hence a funnel: the first layer is wider than the input because it forms features across the whole fan, the second narrow because it composes a judgement already made — and because the linear skip carries the coarse policy to the controls anyway, leaving those four units only the nonlinear correction to it.

An earlier draft used 8 → 8 → 6 → 2 at 156 parameters, which was cheaper and wrong: eight units reading eight inputs form no features, they only pass the vector along.

05Two flaws in the search itself

Both live in genetic.py, so both are shared by every entrant equally and advantage nobody. Neither was found by looking at fitness; both were found by looking at what the algorithm actually does.

The mutation was as large as the weights

σ = 0.30, fixed → σ: 0.30 → 0.03, geometric

A typical weight is 0.271, so σ/|w| was 1.11: a mutated gene was not perturbed but effectively redrawn. And it was as violent at generation 120 as at generation 1, so nothing could be refined late in a run and only the untouched elites carried progress. Geometric rather than linear, because the useful quantity is the ratio of the step to the weights — equal fractions of the run should shrink it by equal factors.

The ranking was computed and then discarded

parents drawn uniformly → log-decreasing rank weights

Selection produced a ranking — the top 30% — and the very next line drew parents uniformly inside it, so the best genome in the pool and the one scraping the cut-off bred equally often. Rank weighting is what the evolution-strategy literature settles on: the population's shift from one generation to the next is a noisy estimate of the direction fitness improves in, and this is the weighting that estimates it best. Effective pool size goes from 30 to 16.6 — the ranking is used without the diversity collapsing.

Neither is measured. Thirty generations on three seeds could not separate the new search from the old, and the seed-to-seed spread on this problem is 0.04 to 3.05 laps on one architecture. They are bets on the argument.

A third idea was rejected on the same evidence. Cutting the population to 20 and running 600 generations sounds like it follows from CMA-ES's default λ = 4 + 3·ln(d) ≈ 19, but that default assumes a deterministic objective and a far more informed algorithm. Under noise the theory says the opposite. At population 20 the breeding pool is six genomes, effective size 3.7, and four elites are a fifth of the population: the search would spend 600 generations refining a winner picked at random around generation 10.

06The brief leaked the incumbent's design

One entry arrived with the incumbent's exact architecture — mirror symmetry, one hidden layer of twelve, a linear skip, 150 parameters. The obvious explanation was convergent design. The real one was worse.

The symmetry hint had been removed from the brief's rationale and left in three other places the agents necessarily receive: the list of operations the rules explicitly permit ("reordering the sensors, mirroring them, and plain linear combinations are fine"), a docstring example, and a checkpoint comment naming symmetric — the incumbent's own configuration flag — by name. All three are closed now. For that entry it is too late.

It is not unfair between the entrants: all three received the identical brief, and the other two chose differently. And it resolved itself when the incumbent moved to a funnel — what remains is a controlled comparison of depth against width at the same symmetry, the same skip and a near-identical budget, which is more informative than four arbitrary architectures.

07What the instruments showed, and what they later corrected

The strip under the circuit carries progress, genetic spread and best-per-circuit. The third was built because the per-circuit scores were being aggregated into one fitness before anything could look at them. It immediately showed something no fitness number could — and then, seventeen generations later, corrected a conclusion drawn from its own first reading.

Not memorisation. Specialisation — and the fitness function asked for it

The obvious worry about an entrant that dominates one circuit is that it has learnt that circuit by heart. It cannot have: the networks are memoryless, seeing only the current rays, with no idea where on the lap they are or what came before. A sequence of corners is not something they can encode. The start point also moves every generation and the islands rotate through four layouts.

What it can do is specialise to one circuit's distribution of sensor states — and at generation 23 that is exactly what the numbers showed. The incumbent was first on grid-city and third on both of the others. Not better in general: better there. And worst + 0.35 × mean rewards precisely that, since it leads with the circuit an entrant is worst on. The network was answering the objective correctly. The objective is not the race, which is one lap of one circuit with no worst-case term at all.

08Three circuits, only one of which was doing anything

The same breakdown exposed the training set. Counting corners tight enough to force a car below half of top speed — the turning radius is speed / 4.5°, so this is geometry, not judgement — the four circuits were not four problems:

Grid-city was the only circuit that discriminated. Speedway was saturated — three entrants at or past the three-lap frame budget, which separates nobody. And the race circuit, the one every entrant is finally ranked on, was tied for easiest: the finals were the least demanding thing on the calendar.

Each fix is the geometry rather than a difficulty dial. A hairpin's radius is half the lane spacing, so serpentine's were 75 px and takeable at 98% of top speed; six lanes at 98 px spacing fixes that but needs a road so narrow that all five islands are silently skipped, so the corners come from the straights instead — six bumps rather than three, two smoothing passes rather than four so they stay corners. Speedway's chicane was drawn with real direction changes and then rounded away by three Chaikin passes; one pass leaves it as drawn. Gauntlet went from nine peaks at 72 px to eleven at 90.

Grid-city lost four of its twelve right angles — in the skeleton, not by smoothing, because square corners are its whole character. Not because twelve was impossible. That was the first conclusion, from the compound odds: at 90% per corner a twelve-corner lap survives 28% of the time. The arithmetic was right and the inference was not — by generation 40 an entrant was lapping it at 2.72. Twelve corners was learnable, just far more slowly than the rest, and while that lasted the compound odds ranked the entrants rather than their driving.

Two frames over three laps

1089 frames against 1091 — three hundredths of a second at 60 fps, after eighteen seconds of racing. The hand-written entry won, and by a margin that says nothing about which architecture is better. It says the two are indistinguishable on this circuit, and that a different seed or a different start point would as easily have reversed it.

That margin is only visible at all because the race was rebuilt to measure it. Ranking by distance covered in a fixed number of frames — what it did before — reported this as "3.43 laps against 3.42" and left the reader to wonder whether that was a result or a rounding artefact.

Gemini went from first to last, and it is not clear why

On the unbalanced circuits at generation 40, gemini led on all three, at 3.72 against the incumbent's 2.83. On the rebalanced ones it finished on 1.95 — half of everyone else — and crashed out of the race at 1.82 laps.

The honest position is that this is unexplained. Its architecture is the one that does not impose mirror symmetry and splits into two independent six-unit streams, so a plausible story is that the old circuit mix suited it and the new one does not. But a single run per configuration on a search whose seed-to-seed spread is 0.04 to 3.05 laps cannot tell a real effect from a bad draw, and no second run was done. Treat the ranking below the top two as one sample, not as a finding.

What the race had to become first

A screenshot where the log said one thing and the picture said another turned out to be three separate defects.

26 px apart along the lap → side by side across the road

Staggering the grid along the centreline was fair — distance is counted from each car's own start — and made the picture lie: the eventual winner started 72 px back, so it could lead on distance while looking level. In a race that exists to be watched, a leader you cannot see is a defect.

furthest at the time limit → first past three laps

The two pick the same winner only while nobody crashes, which is not the usual case. A car that crosses the line now parks, so the others race on and get a time of their own — the previous version froze the runner-up a hundredth of a lap short and called it "still running".

GEN 200 · mutation 0.030 → RACE · running order

The panel did not know it was in a race: it displayed generations, mutation size and evaluations spent, and the three analyses read "collecting..." for the whole twenty seconds because a race has no history to plot. It now shows the order and each car's progress to the flag — after a three-second countdown, which changes no result and makes the recording start like a race rather than mid-corner.

What the result does not settle

  • Depth against width. The whole point of 8 → 10 → 4 → 2 against 8 → 12 → 2 was to test whether a funnel beats one wide layer at the same budget, everything else held. Two frames in eighteen seconds is not an answer; it is a tie reported to more decimal places than it has.
  • Whether the search changes helped. The annealed mutation and the rank-weighted parents went in on argument, not evidence, and this run cannot separate their effect from the circuit rebalance that happened at the same time.
  • What happened to gemini. First on the old circuits, last on the new ones, one sample each.
  • 120 generations or 250. At 160 parameters the budget is 75 evaluations per parameter, under the rule of thumb's floor — and it binds codex, at 344, hardest of all.

10Errors, and what they cost

Kept because a design record that lists only the decisions that worked is not a record. Several of these were plausible arguments that measurement later contradicted, and two are conclusions in this document's own earlier version.

  • overread

    A snapshot at 19% of a run was reported as a finding

    Generation 23 put the incumbent's per-corner reliability at 93% against the field's 83%. By generation 40 another entrant led on all three circuits. The estimate was sound; treating one generation of a stochastic search as a result was not.

  • overread

    Grid-city was called near-impossible

    Twelve corners at 90% each is a 28% lap — correct arithmetic describing the opening phase, not the circuit. An entrant reached 2.72 laps on it. The rebalance went from six corners back to eight on that evidence.

  • ×60

    A full recording was costed at 71 hours

    257 280 frames at 60 fps is 71 minutes. The error made keeping every frame look prohibitive and produced a clip-and-cut system to avoid a problem that did not exist. Recording everything is now the default.

  • design

    The first recorder kept one frame in thirty

    At 60 fps that is a car crossing an entire corner between frames: a slideshow, not a video. True at capture and equally true of a 20× playback speed-up — but 4–6× is smooth, which is the range anyone actually wants, and generalising the extreme to all of it was wrong.

  • silent

    A new parameter was added to a signature and never passed on

    build_car took the grid's lateral offset and called Car(...) without it, so every car started in the same spot and the new grid did nothing — visibly nothing, but nothing that raised anything. Caught by the test written alongside it.

  • derived

    The race time limit was a fraction of the training budget

    Scaled as budget x laps / 2, which made a 0.05-lap race come out as thirty frames — long enough for a car to move and not to finish. It is now twice what the distance takes at top speed, derived from the distance rather than from an unrelated number.

  • caught

    A six-lane serpentine silently dropped all five islands

    A road narrow enough for 98 px lane spacing leaves 18 px for an island against a 26 px corridor each side, so every one was skipped without a word. Found by counting them before shipping, not after.

  • destroyed

    A smoke test overwrote the trained champion

    outputs/ is gitignored, so no copy existed. Retrained: 3.19 laps against the 3.23 in the README.

  • parity

    Start points were drawn from the genome generator

    Genome size decided how many numbers had been consumed, so differently sized entrants met different starts from generation 1. Fixed with a dedicated stream, proved before and after.

  • false

    The brief claimed adjacent genes help crossover

    They do not: crossover is uniform, position is irrelevant. One entrant had already designed contiguous 14-gene blocks around the claim.

  • leak

    Three files told the agents about the mirror symmetry

    See section 06. One entry was built on it.

  • crash

    The panel read attributes only the incumbent had

    layer_sizes and weights, so any competitor took the window down on the first frame it led. Replaced by describe() with a measured-response fallback.

  • wrong

    Advice to close the editor to free CPU

    The ablation was running inside that editor's integrated terminal. Closing it would have killed the run.

  • wrong

    A refactor was skipped for a reason that did not hold

    The claim was that float32 → float64 accumulation would shift every result. Measured: the clearance field holds integers 0–49, accumulation is exact in both widths, zero divergences in 3924 casts. Taking it was a 2.34× speed-up.

  • removed

    The per-generation curve was deleted on a bad argument

    "They all move together" is true but not a reason: the differences between those lines are exactly where one entrant handles a hard draw better than another. Restored, faint, beneath the running maximum.

  • invisible

    Three new analyses shipped that nobody could see

    The window asked for 980 px of height on a 900 px display, and the layout dropped the strip rather than shrinking anything. The circuit now scales to make room for it.

  • counting

    The time remaining climbed instead of falling

    It divided elapsed time by the generation in progress: the numerator grew while the divisor did not. Now the mean of the last five finished generations.

  • luck

    A layout test passed by coincidence

    It asserted a difference between two screen sizes that happen to yield the same scale, and survived only on the short-circuit of an and.
